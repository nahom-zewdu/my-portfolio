# Portfolio Vision

## Purpose

The portfolio should communicate:

1. I build difficult things.
2. I know what I'm doing.
3. I think deeply about systems.

## What it is NOT

- Startup landing page
- Personal blog
- Designer portfolio
- AI-themed website
- Terminal-themed website

## Design Language

Engineering Notebook

The site should feel like reading the notes of a systems engineer.

Keywords:

- Editorial
- Structured
- Intentional
- Calm
- Technical
- Confident

Avoid:

- Flashy animations
- Glassmorphism
- Gradients
- Neon colors
- Excessive motion
- Bento grids

## Experience

Present experience as concise, outcome-oriented summaries rather than a timeline.

Focus on:

- responsibilities
- systems built
- technical impact

Keep entries short and specific:

- owned platform reliability and API surface for high-throughput systems
- built observability tooling, deployment automation, and runtime resilience
- translated product goals into service architecture, data pipelines, and operational guardrails

Avoid role chronology and lengthy date-based narratives.

## Layout

Persistent left navigation.
Scrollable content area.

## Typography

Typography is the primary visual identity.

Large headings.
Generous whitespace.

## Color System

Use a restrained accent palette anchored in muted amber / aged brass.

Use color only for:

- active navigation
- section labels
- links
- notebook markers

Avoid:

- gradients
- colorful backgrounds
- large accent surfaces

Maintain a calm engineering aesthetic with low-key contrast and purposeful color usage.

## Motion

Add subtle motion only where it improves usability.

Focus on:

- hover states
- navigation transitions
- section interactions

Constraints:

- maximum 200ms duration
- no decorative animations
- no parallax
- no floating effects
